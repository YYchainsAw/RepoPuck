# RepoPuck v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-ready Windows tray Git client with a draggable puck, dockable Primer-styled panel, real repository status, file staging, branch switching, committing, pushing, safe secondary operations, settings, tests, and packaging.

**Architecture:** Tauri 2 provides the native Windows shell, Git command execution, persistent settings, tray, and two-window lifecycle. React and TypeScript provide a typed, testable UI behind a `GitClient` interface, with browser development using an in-memory demo client and packaged builds using Tauri `invoke`.

**Tech Stack:** Tauri 2, Rust 2021, React 19, TypeScript, Vite, Primer React, Primer Octicons, Vitest, Testing Library, ESLint, rustfmt, Clippy.

## Global Constraints

- Support Windows in v0.1 and require an installed Git executable on PATH.
- Do not require or implement GitHub login; remote authentication remains with Git Credential Manager or SSH.
- Match `docs/references/floating-panel-light.png` using GitHub Primer light tokens and use `docs/references/jetbrains-change-groups.png` only for file grouping and split commit actions.
- Group files as `Changes` and `Unversioned files`; render `Commit` and `Commit & Push` as separate actions.
- Use Primer Octicons for UI icons and generated raster assets for the application icon; do not handcraft SVGs, CSS art, glyph icons, gradients, or emoji.
- Run Git through argument arrays without a shell and insert `--` before user-controlled paths.
- Keep merge, rebase, cherry-pick, destructive reset, conflict editing, and remote management outside v0.1.
- Follow test-first development for new behavior, make small coherent commits, and push only at release checkpoints.
